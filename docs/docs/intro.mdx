# Introduction

:::caution[Unstable APIs until 0.5.0]
Scene authoring is Python. Murali's renderer is written in Rust for performance, but animation and
visual authoring should happen in Python.

The Python and kit APIs will keep changing until **0.5.0**. After that, they are meant to stay
stable.

If you want to author scenes in Rust today, use the last Rust-authoring release:
[`murali` 0.2.4](https://crates.io/crates/murali/0.2.4) and the
[0.2.4 docs](/docs/0.2.4/intro).
:::

Murali is a Python-first animation engine for mathematical, AI, and teaching visuals. You write
scenes in Python. A Rust runtime underneath squeezes maximum performance from a modern GPU stack
(`wgpu`: Metal, Vulkan, DirectX).

The public authoring path is Python:

```bash
python3 -m pip install murali-kit
```

That installs Murali Kit and a compatible `murali-engine`. You do not need a local Rust toolchain
on macOS, Linux, or Windows when a prebuilt wheel is available.

```python
from murali_engine import Circle, Label, Scene, Timeline
from murali_kit.colors import GREEN_D, WHITE
from murali_kit.themes import DarkTheme

scene = Scene()
scene.apply_theme(DarkTheme())
title = scene.add(Label("Hello Murali", height=0.38, color=WHITE), at=(0.0, 2.4, 0.0))
circle = scene.add(Circle(radius=1.2, color=GREEN_D).with_stroke(0.04, WHITE))

timeline = Timeline()
timeline.animate(title).at(0.0).for_duration(1.0).typewrite_text().spawn()
timeline.animate(circle).at(0.4).for_duration(1.2).ease("out_cubic").draw().spawn()
scene.play(timeline)
scene.preview()
```

Two packages:

- **`murali-engine`** — the Python frontend over the Rust runtime: scene, tattvas, timeline,
  camera, preview, export
- **`murali-kit`** — themes, named colors, examples, and reusable teaching components

If you need to build your own integration, authoring workflow, or higher-level visual toolkit,
start from the Python frontend layer. Use the Rust crate directly only when you are embedding the
runtime or working on the engine itself.

Murali is also being grown as an AI visualization engine for technical education. See
[AI Visualization](./ai-visualization) for the public category roadmap.

## Why Murali?

Murali is built for narration-first and lesson-first work: you already know when a sentence lands,
and the picture has to hit that time.

- **Python authoring** — scenes, timelines, teaching views, and integrations in ordinary Python
- **Time-driven animation** — properties are functions of time, not frame recipes
- **World space** — positions and sizes are mathematical units, not pixels
- **Rust performance core** — GPU rendering through `wgpu` on Metal, Vulkan, and DirectX 12
- **A small language** — Scene, tattva, timeline, then kit components on top

## Why not Murali?

Murali is new. The first public release was in April 2026. APIs are still evolving, and the project
is intentionally focused on Python-authored teaching visuals, deterministic timelines, and a fast
Rust rendering engine.

Murali is being shaped in part by production use at [Kavriq](https://kavriq.com). If you have a
specific use case, please share it on
[GitHub Discussions](https://github.com/murali-engine/murali/discussions).

## Core concepts

- **Tattva** — any object in a scene (shape, text, or composite). From Sanskrit: “element” or “essence.”
- **Scene** — owns tattvas, the timeline, the camera, and the frame
- **Frame** — landscape, portrait, or square composition
- **Timeline** — when properties change, and for how long
- **World space** — coordinates in mathematical units, not pixels
- **Kit** — themes, named colors, and teaching views built from engine primitives

The workflow is:

```text
Create a scene → add tattvas → build a timeline → play it → preview or export
```

## Your First Scene

A slightly fuller example: a title and two shapes that swap sides.

```python
from murali_engine import Circle, Label, Scene, Square, Timeline
from murali_kit.colors import GREEN_D, RED_B, WHITE
from murali_kit.themes import DarkTheme

scene = Scene()
scene.apply_theme(DarkTheme())

title = scene.add(Label("My First Scene", height=0.38, color=WHITE))
scene.to_edge(title, "up", margin=0.8)

square = scene.add(
    Square(size=1.2, color=RED_B).with_stroke(0.04, WHITE),
    at=(-4.0, 0.0, 0.0),
)
circle = scene.add(
    Circle(radius=0.65, color=GREEN_D, segments=48).with_stroke(0.04, WHITE),
    at=(4.0, 0.0, 0.0),
)

timeline = Timeline()
timeline.animate(square).at(0.0).for_duration(2.0).ease("in_out_quad").move_to((2.0, 0.0, 0.0)).spawn()
timeline.animate(circle).at(0.5).for_duration(2.0).ease("out_quad").move_to((-2.0, 0.0, 0.0)).spawn()
scene.play(timeline)
scene.preview()
```

## Why timeline-based animation?

1. **Determinism** — the picture is a function of time, so it is reproducible
2. **Narration-first timing** — you can hit an exact timestamp
3. **Seeking** — timeline-authored state can be reconstructed at an absolute time, and fails
   explicitly when a callback or updater makes that unsafe
4. **Composability** — animations combine as independent functions of time

## Why the name “Murali”?

The name *Murali* comes from the flute of Lord Krishna, which, in Hindu tradition, is said to
produce music so pure that it touches the soul.

The goal of this project is similar: visual storytelling that feels effortless, so ideas flow
clearly from storyteller to viewer.
